8. Performance Testing

In this step, we’ll perform comprehensive load testing to measure the performance improvements achieved by our multi-layer caching architecture.

Step 1: Install Testing Tools

Install Apache Bench

  1. SSH into your EC2 instance and install testing tools:
# Install Apache Bench
sudo yum install -y httpd-tools

# Install additional tools
sudo yum install -y curl wget jq

# Verify installation
ab -V

Install Artillery (Advanced Testing)

  1. Install Artillery for more advanced testing:
# Install Artillery globally
npm install -g artillery

# Verify installation
artillery version

Step 2: Baseline Performance Testing

Test Direct DynamoDB Access

  1. Clear all caches and test direct database access:
# Clear Redis cache
curl -X DELETE https://d1234567890123.cloudfront.net/cache

# Reset statistics
curl -X POST https://d1234567890123.cloudfront.net/stats/reset

# Test direct database access (cold start)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Measure Response Times

  1. Record baseline metrics:
# Run multiple tests and calculate average
for i in {1..10}; do
  echo "Test $i:"
  time curl -s "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" > /dev/null
done

Step 3: Cache Performance Testing

Test Redis Cache Performance

  1. Warm up Redis cache and test:
# Warm up cache
curl -X POST https://d1234567890123.cloudfront.net/cache/warmup

# Test Redis cache hit
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

# Check cache statistics
curl https://d1234567890123.cloudfront.net/stats

Test DAX Cache Performance

  1. Clear Redis but keep DAX cache:
# Clear only Redis cache
curl -X DELETE https://d1234567890123.cloudfront.net/cache/product:PROD001:Electronics

# Test DAX cache hit
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Test CloudFront Cache Performance

  1. Test CloudFront edge cache:
# Make request to warm CloudFront cache
curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

# Test CloudFront cache hit (check X-Cache header)
curl -I "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

# Measure response time
time curl -s "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" > /dev/null

Step 5: Advanced Testing with Artillery

Create Artillery Configuration

  1. Create Artillery test configuration:
nano artillery-test.yml
  1. Add test configuration:
config:
  target: 'https://d1234567890123.cloudfront.net'
  phases:
    - duration: 60
      arrivalRate: 10
      name: "Warm up"
    - duration: 120
      arrivalRate: 50
      name: "Load test"
    - duration: 60
      arrivalRate: 100
      name: "Stress test"
  defaults:
    headers:
      User-Agent: "Artillery Load Test"

scenarios:
  - name: "Product API Test"
    weight: 70
    flow:
      - get:
          url: "/product/PROD001?category=Electronics"
      - get:
          url: "/product/PROD002?category=Electronics"
      - get:
          url: "/product/PROD003?category=Books"
  
  - name: "Products List Test"
    weight: 20
    flow:
      - get:
          url: "/products"
      - get:
          url: "/products?category=Electronics"
  
  - name: "Health Check Test"
    weight: 10
    flow:
      - get:
          url: "/health"
      - get:
          url: "/stats"

Run Artillery Test

  1. Execute the Artillery test:
# Run the load test
artillery run artillery-test.yml

Step 6: Performance Comparison Analysis

Create Performance Comparison Script

  1. Create a script to compare performance across layers:
nano performance-test.sh
  1. Add comparison script:
#!/bin/bash

echo "=== Multi-Layer Caching Performance Test ==="
echo "Testing URL: https://d1234567890123.cloudfront.net"
echo

# Function to test response time
test_response_time() {
    local url=$1
    local description=$2
    echo "Testing: $description"
    
    # Run 5 tests and calculate average
    total=0
    for i in {1..5}; do
        time_ms=$(curl -o /dev/null -s -w "%{time_total}" "$url" | awk '{print $1*1000}')
        total=$(echo "$total + $time_ms" | bc)
        echo "  Test $i: ${time_ms}ms"
    done
    
    average=$(echo "scale=2; $total / 5" | bc)
    echo "  Average: ${average}ms"
    echo
}

# Clear all caches
echo "Clearing all caches..."
curl -s -X DELETE https://d1234567890123.cloudfront.net/cache > /dev/null
curl -s -X POST https://d1234567890123.cloudfront.net/stats/reset > /dev/null
sleep 2

# Test 1: Cold start (DynamoDB only)
test_response_time "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" "Cold Start (DynamoDB)"

# Test 2: DAX cache hit
test_response_time "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" "DAX Cache Hit"

# Test 3: Redis cache hit
test_response_time "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" "Redis Cache Hit"

# Test 4: CloudFront cache hit
test_response_time "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics" "CloudFront Cache Hit"

# Get final statistics
echo "=== Final Cache Statistics ==="
curl -s https://d1234567890123.cloudfront.net/stats | jq '.'
  1. Run the performance comparison:
# Make script executable
chmod +x performance-test.sh

# Run the test
./performance-test.sh

Troubleshooting Performance Issues

Issue: High Response Times

Possible Causes:

  • Cache misses due to TTL expiration
  • Database query performance
  • Network latency

Solutions:

  • Increase cache TTL for stable data
  • Optimize database queries
  • Use CloudFront for global performance

Issue: Low Cache Hit Rates

Possible Causes:

  • Inconsistent cache keys
  • Short TTL values
  • High cache eviction rate

Solutions:

  • Review cache key strategy
  • Increase cache memory allocation
  • Optimize TTL settings

Issue: System Overload

Possible Causes:

  • Insufficient instance resources
  • Database connection limits
  • Cache memory exhaustion

Solutions:

  • Scale up instance types
  • Implement connection pooling
  • Monitor and tune cache memory

Performance Optimization Recommendations

Immediate Optimizations

  1. Increase Redis memory for higher cache capacity
  2. Tune TTL values based on data update frequency
  3. Implement cache warming for critical data

Long-term Improvements

  1. Auto Scaling Groups for horizontal scaling
  2. Read Replicas for database scaling
  3. Multi-region deployment for global performance
