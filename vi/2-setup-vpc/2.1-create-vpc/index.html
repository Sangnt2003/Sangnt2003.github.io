Tạo VPC

Trong bước này, chúng ta sẽ tạo một Virtual Private Cloud (VPC) với tất cả các thành phần mạng cần thiết cho kiến trúc caching đa tầng của chúng ta.

Bước 1: Điều Hướng Đến VPC Console

  1. Mở AWS Management Console
  2. Điều hướng đến VPC service

  1. Nhấp Create VPC

Bước 2: Chọn Phương Thức Tạo VPC

  1. Chọn VPC and more để tạo VPC với các tài nguyên liên quan

Tùy chọn “VPC and more” tự động tạo subnets, route tables, internet gateway, và NAT gateways, tiết kiệm thời gian và đảm bảo cấu hình đúng.

Bước 3: Cấu Hình Cài Đặt VPC

Cấu Hình VPC Cơ Bản

  1. Cấu hình các cài đặt VPC cơ bản:

    • Name tag auto-generation: caching-workshop
    • IPv4 CIDR block: 10.0.0.0/16
    • IPv6 CIDR block: No IPv6 CIDR block
    • Tenancy: Default

Cấu Hình Subnet

  1. Cấu hình subnets cho tính khả dụng cao:

    • Number of Availability Zones: 2
    • Number of public subnets: 2
    • Number of private subnets: 2

Cấu Hình NAT Gateway

  1. Cấu hình NAT gateways cho truy cập internet outbound:

    • NAT gateways: 1 per AZ
    • VPC endpoints: None (cho workshop này)

Sử dụng 1 NAT gateway mỗi AZ cung cấp tính khả dụng cao nhưng tăng chi phí. Để tối ưu chi phí trong môi trường non-production, bạn có thể sử dụng 1 NAT gateway tổng cộng.

Bước 4: Tạo VPC

  1. Nhấp Create VPC

Việc tạo VPC sẽ mất 2-3 phút. Quá trình này tạo tất cả các tài nguyên liên quan bao gồm subnets, route tables, internet gateway, và NAT gateways.

Bước 7: Ghi Lại Thông Tin Quan Trọng

Ghi lại thông tin sau để sử dụng trong các bước tiếp theo:

Thông Tin VPC

  • VPC ID: vpc-xxxxxxxxx
  • VPC CIDR: 10.0.0.0/16

Thông Tin Subnet

  • Public Subnet 1: subnet-xxxxxxxxx (AZ: us-east-1a)
  • Public Subnet 2: subnet-xxxxxxxxx (AZ: us-east-1b)
  • Private Subnet 1: subnet-xxxxxxxxx (AZ: us-east-1a)
  • Private Subnet 2: subnet-xxxxxxxxx (AZ: us-east-1b)

Giữ thông tin này tiện dụng vì bạn sẽ cần các ID này khi tạo security groups, khởi chạy instances, và cấu hình các dịch vụ AWS khác.

Khắc Phục Các Vấn Đề Thường Gặp

Vấn Đề: Tạo VPC Thất Bại

Nguyên Nhân Có Thể:

  • Quyền không đủ
  • Xung đột CIDR block
  • Đạt giới hạn dịch vụ

Giải Pháp:

  • Xác minh quyền IAM bao gồm quyền tạo VPC
  • Chọn CIDR block khác
  • Kiểm tra giới hạn dịch vụ AWS trong tài khoản của bạn

Vấn Đề: Tạo NAT Gateway Thất Bại

Nguyên Nhân Có Thể:

  • Không đủ Elastic IP addresses
  • Public subnet không được cấu hình đúng

Giải Pháp:

  • Yêu cầu thêm Elastic IP addresses
  • Xác minh public subnets có routes đến Internet Gateway

Các Bước Tiếp Theo

Hạ tầng VPC của bạn giờ đã sẵn sàng! Bạn có:

✅ VPC với phân bổ CIDR phù hợp
✅ Triển khai Multi-AZ cho tính khả dụng cao
✅ Public subnets cho các tài nguyên hướng internet
✅ Private subnets cho các dịch vụ backend
✅ Internet Gateway cho truy cập internet public
✅ NAT Gateways cho kết nối outbound an toàn

Tiếp theo, chúng ta sẽ tạo security groups để kiểm soát truy cập mạng giữa các dịch vụ của chúng ta.
