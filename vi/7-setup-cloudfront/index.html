7. Thiết Lập CloudFront CDN

Trong bước này, chúng ta sẽ tạo một CloudFront distribution để cung cấp global edge caching cho ứng dụng multi-layer caching của chúng ta.

Bước 1: Điều Hướng Đến CloudFront Console

  1. Mở AWS Management Console
  2. Điều hướng đến CloudFront service
  3. Nhấp Create distribution

Bước 2: Cấu Hình Origin Settings

Origin Domain

  1. Cấu hình origin settings:

    • Origin domain: Nhập ALB DNS name của bạn 
      caching-app-alb-xxxxxxxxx.us-east-1.elb.amazonaws.com
    • Protocol: HTTP only (cho workshop)
    • HTTP port: 80

Origin Path

  1. Cấu hình origin path (tùy chọn):

    • Origin path: Để trống
    • Name: Auto-generated dựa trên domain

Additional Origin Settings

  1. Cấu hình additional settings:

    • Add custom header: None
    • Enable Origin Shield: No (cho workshop)

Bước 3: Cấu Hình Default Cache Behavior

Path Pattern

  1. Cấu hình cache behavior:

    • Path pattern: Default (*)
    • Compress objects automatically: Yes

Viewer Protocol Policy

  1. Cấu hình viewer protocol:

    • Viewer protocol policy: Redirect HTTP to HTTPS
    • Allowed HTTP methods: GET, HEAD, OPTIONS, PUT, POST, PATCH, DELETE

Cache Key and Origin Requests

  1. Cấu hình cache key settings:

    • Cache policy: Tạo policy mới hoặc sử dụng existing
    • Origin request policy: None
    • Response headers policy: None

Create Custom Cache Policy

  1. Nhấp Create policy để tạo custom cache policy:

    • Name: CachingAppPolicy
    • Description: Cache policy for caching application
    • Default TTL: 300 seconds (5 phút)
    • Maximum TTL: 3600 seconds (1 giờ)
    • Minimum TTL: 0 seconds

Cache Key Settings

  1. Cấu hình cache key settings:

    • Headers: None
    • Query strings: All
    • Cookies: None

  2. Nhấp Create

Bước 4: Cấu Hình Distribution Settings

Price Class

  1. Cấu hình distribution settings:

    • Price class: Use all edge locations (best performance)
    • AWS WAF web ACL: None

Alternate Domain Names

  1. Cấu hình domain settings:

    • Alternate domain names (CNAMEs): Để trống cho workshop
    • Custom SSL certificate: Default CloudFront certificate

Default Root Object

  1. Cấu hình default root object:

    • Default root object: Để trống
    • Standard logging: Off (cho workshop)

Description and Comments

  1. Thêm description:

    • Description: CloudFront distribution for multi-layer caching workshop
    • Distribution state: Enabled

Bước 5: Review và Create

Review Configuration

  1. Review tất cả settings
  2. Nhấp Create distribution

Việc triển khai CloudFront distribution mất 15-20 phút. Distribution sẽ hiển thị trạng thái “Deploying” trong thời gian này.

Bước 6: Giám Sát Distribution Deployment

Kiểm Tra Deployment Status

  1. Giám sát distribution deployment
  2. Trạng thái sẽ thay đổi từ “Deploying” thành “Enabled”

Ghi Lại Distribution Domain

  1. Sau khi deployed, ghi lại Distribution domain name: 
d1234567890123.cloudfront.net

Bước 7: Test CloudFront Distribution

Test Basic Connectivity

  1. Test CloudFront distribution:
# Test health endpoint through CloudFront
curl https://d1234567890123.cloudfront.net/health

Test Application Endpoints

  1. Test tất cả application endpoints:
# Test product endpoint
curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

# Test products list
curl "https://d1234567890123.cloudfront.net/products"

# Test cache statistics
curl https://d1234567890123.cloudfront.net/stats

Bước 8: Cấu Hình Cache Behaviors

Create API Cache Behavior

  1. Đi đến tab Behaviors và nhấp Create behavior

  2. Cấu hình API-specific caching:

    • Path pattern: /product/*
    • Origin: ALB origin của bạn
    • Cache policy: Tạo policy mới cho API

API Cache Policy

  1. Tạo API cache policy:

    • Name: APIResponsePolicy
    • Default TTL: 300 seconds
    • Maximum TTL: 600 seconds
    • Query strings: All
    • Headers: Include Authorization nếu cần

Create Stats Behavior

  1. Tạo behavior cho stats endpoint:

    • Path pattern: /stats
    • Cache policy: Tạo no-cache policy
    • TTL: 0 seconds (no caching)

Bước 9: Test Cache Performance

Test Cache Miss

  1. Clear bất kỳ existing cache nào và test:
# First request (cache miss)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Test Cache Hit

  1. Thực hiện cùng request lần nữa:
# Second request (cache hit)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Check Response Headers

  1. Kiểm tra CloudFront cache headers:
# Check cache headers
curl -I "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Tìm các headers như:

  • X-Cache: Hit from cloudfront (cache hit)
  • X-Cache: Miss from cloudfront (cache miss)
  • Age: 120 (thời gian kể từ khi cached)

Bước 10: Cấu Hình Cache Invalidation

Create Invalidation

  1. Đi đến tab Invalidations và nhấp Create invalidation

  2. Cấu hình invalidation paths:

    • Object paths: 
      /product/*
/products
/stats

  3. Nhấp Create invalidation

Monitor Invalidation

  1. Giám sát invalidation progress

Invalidations mất 5-15 phút để hoàn thành qua tất cả edge locations.

Bước 11: Giám Sát CloudFront Performance

CloudWatch Metrics

  1. Đi đến tab Monitoring để xem metrics

Các metrics chính cần giám sát:

  • Requests: Số lượng requests đến CloudFront
  • BytesDownloaded: Dữ liệu transferred đến viewers
  • CacheHitRate: Phần trăm requests được serve từ cache
  • OriginLatency: Response time từ origin
  • 4xxErrorRate: Client error rate
  • 5xxErrorRate: Server error rate

Real-time Logs (Tùy chọn)

  1. Enable real-time logs cho detailed monitoring

Bước 12: Performance Comparison

Test Performance Improvement

  1. So sánh response times:
# Direct ALB access
time curl "http://caching-app-alb-xxxxxxxxx.us-east-1.elb.amazonaws.com/product/PROD001?category=Electronics"

# CloudFront access (after cache warm-up)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Global Performance Test

  1. Test từ các locations khác nhau sử dụng online tools:
  • GTmetrix: Test từ nhiều global locations
  • Pingdom: Global performance monitoring
  • WebPageTest: Detailed performance analysis

Bước 13: Ghi Lại CloudFront Configuration

Ghi lại thông tin sau:

CloudFront Distribution Information

  • Distribution ID: E1234567890123
  • Domain Name: d1234567890123.cloudfront.net
  • Origin: ALB DNS name
  • Status: Enabled
  • Price Class: All edge locations

Cache Behaviors

  • Default: 5-minute TTL, all query strings
  • API Endpoints: 5-minute TTL, optimized cho API responses
  • Stats Endpoint: No caching cho real-time data

Performance Characteristics

  • Global latency: 10-50ms (tùy thuộc edge location)
  • Cache hit ratio target: 80%+
  • Origin offload: 70%+ reduction trong origin requests

Khắc Phục Các Vấn Đề Thường Gặp

Vấn Đề: Distribution Không Truy Cập Được

Nguyên Nhân Có Thể:

  • Distribution vẫn đang deploying
  • Origin không accessible
  • DNS propagation delay

Giải Pháp:

  • Đợi deployment hoàn thành (15-20 phút)
  • Test origin trực tiếp trước
  • Sử dụng distribution domain name, không phải custom domain

Vấn Đề: Cache Miss Rate Cao

Nguyên Nhân Có Thể:

  • Query strings không được cấu hình đúng
  • Headers ảnh hưởng cache key
  • TTL quá ngắn

Giải Pháp:

  • Review cache policy configuration
  • Kiểm tra query string và header settings
  • Tăng TTL cho stable content

Vấn Đề: Origin Errors

Nguyên Nhân Có Thể:

  • ALB hoặc application issues
  • Security group chặn CloudFront
  • Origin timeout

Giải Pháp:

  • Kiểm tra ALB và application health
  • Xác minh security groups cho phép CloudFront IPs
  • Tăng origin timeout settings

Security Best Practices

Origin Access Control

  • Restrict origin access: Chỉ cho phép CloudFront truy cập ALB
  • Security groups: Update ALB security group để chỉ cho phép CloudFront

SSL/TLS Configuration

  • Viewer protocol: Redirect HTTP to HTTPS
  • Origin protocol: Sử dụng HTTPS khi có thể
  • Security headers: Thêm security headers qua response headers policy

Các Bước Tiếp Theo

CloudFront distribution của bạn giờ đã được cấu hình và tối ưu! Bạn có:

✅ Global CDN với edge locations trên toàn thế giới
✅ Edge caching giảm origin load
✅ Custom cache behaviors cho các loại content khác nhau
✅ Cache invalidation cho content updates
✅ Performance monitoring với CloudWatch metrics
✅ SSL/TLS termination cho secure connections

Lợi Ích CloudFront Đã Đạt Được:

  • Global performance: Low latency từ edge locations trên toàn thế giới
  • Origin protection: Giảm load trên ALB và application servers
  • DDoS protection: Built-in AWS Shield protection
  • Cost optimization: Giảm data transfer costs từ origin

CloudFront cache hit rates thường cải thiện theo thời gian khi nhiều content được cached tại edge locations. Giám sát cache hit rate và điều chỉnh TTL settings khi cần.

Tiếp theo, chúng ta sẽ thực hiện comprehensive performance testing để đo lường các cải thiện từ kiến trúc multi-layer caching của chúng ta.
