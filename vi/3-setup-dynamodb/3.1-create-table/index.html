Tạo DynamoDB Table

Trong bước này, chúng ta sẽ tạo một DynamoDB table để lưu trữ dữ liệu product catalog của chúng ta. Table này sẽ phục vụ như source of truth cho kiến trúc multi-layer caching của chúng ta.

Bước 1: Điều Hướng Đến DynamoDB Console

  1. Mở AWS Management Console
  2. Điều hướng đến DynamoDB service

  1. Nhấp Create table

Bước 2: Cấu Hình Table Settings

Cấu Hình Table Cơ Bản

  1. Nhập table configuration:

    • Table name: ProductCatalog
    • Partition key: ProductID (String)
    • Sort key: Category (String)

Chúng ta đang sử dụng composite primary key (partition key + sort key) để cho phép nhiều products trong các categories khác nhau và enable efficient queries.

Table Settings

  1. Cấu hình table settings:

    • Table settings: Default settings
    • Read/write capacity settings: On-demand

On-demand billing hoàn hảo cho workshops và unpredictable workloads. Bạn chỉ trả tiền cho read và write requests mà bạn sử dụng.

Advanced Settings (Tùy chọn)

  1. Mở rộng Additional settings nếu bạn muốn cấu hình:

    • Table class: Standard
    • Encryption: Owned by Amazon DynamoDB
    • Point-in-time recovery: Disabled (cho workshop)
    • Deletion protection: Disabled (cho workshop)

Bước 8: Ghi Lại Table Information

Ghi lại thông tin sau để sử dụng trong các bước tiếp theo:

Table Information

  • Table Name: ProductCatalog
  • Table ARN: arn:aws:dynamodb:us-east-1:123456789012:table/ProductCatalog
  • Partition Key: ProductID (String)
  • Sort Key: Category (String)
  • Billing Mode: On-demand

Sample Data Summary

  • Total Items: 5 products
  • Categories: Electronics (3), Books (2)
  • Price Range: $49.99 - $999.99

Performance Characteristics

Expected Performance

  • Read Latency: 1-10ms (không có DAX)
  • Write Latency: 1-10ms
  • Throughput: Lên đến 40,000 RCU/WCU mỗi partition
  • Consistency: Eventually consistent reads (default)

Optimization Tips

  • Hot Partitions: Giám sát uneven access patterns
  • Item Size: Giữ items dưới 400KB để có hiệu suất tốt nhất
  • Query Patterns: Thiết kế keys để hỗ trợ access patterns của bạn
  • Indexes: Sử dụng GSI/LSI cho additional query patterns

Khắc Phục Các Vấn Đề Thường Gặp

Vấn Đề: Table Creation Thất Bại

Nguyên Nhân Có Thể:

  • Invalid table name hoặc key names
  • Insufficient permissions
  • Service limits reached

Giải Pháp:

  • Chỉ sử dụng alphanumeric characters và underscores
  • Xác minh IAM permissions bao gồm DynamoDB actions
  • Kiểm tra AWS service limits

Vấn Đề: Không Thể Add Items

Nguyên Nhân Có Thể:

  • Missing required key attributes
  • Item size quá lớn
  • Invalid JSON format

Giải Pháp:

  • Đảm bảo ProductID và Category được cung cấp
  • Giữ items dưới 400KB
  • Validate JSON syntax

Vấn Đề: Queries Return No Results

Nguyên Nhân Có Thể:

  • Incorrect key values
  • Case sensitivity issues
  • Wrong query syntax

Giải Pháp:

  • Xác minh exact key values
  • Kiểm tra case-sensitive matches
  • Sử dụng PartiQL editor để test queries

Các Bước Tiếp Theo

DynamoDB table của bạn giờ đã sẵn sàng với sample data! Bạn có:

✅ ProductCatalog table với composite primary key
✅ Sample product data qua nhiều categories
✅ On-demand billing cho cost optimization
✅ CloudWatch monitoring enabled
✅ Query functionality tested và verified

DynamoDB cung cấp single-digit millisecond latency, nhưng chúng ta sẽ thêm DAX để đạt được microsecond latency cho frequently accessed data.

Tiếp theo, chúng ta sẽ thiết lập DynamoDB Accelerator (DAX) để cung cấp microsecond-latency caching cho table của chúng ta.
