4. Thiết Lập ElastiCache Redis

Trong bước này, chúng ta sẽ tạo một ElastiCache Redis cluster sẽ phục vụ như application-level cache. Đây sẽ là tầng caching đầu tiên mà ứng dụng của chúng ta kiểm tra trước khi fallback về DAX và DynamoDB.

Bước 1: Điều Hướng Đến ElastiCache Console

  1. Mở AWS Management Console
  2. Điều hướng đến ElastiCache service

  1. Nhấp Get started hoặc Create nếu đây là lần đầu tiên

Bước 2: Tạo Subnet Group

Điều Hướng Đến Subnet Groups

  1. Nhấp Subnet groups ở navigation bên trái

  2. Nhấp Create subnet group

Cấu Hình Subnet Group

  1. Nhập chi tiết subnet group:

    • Name: redis-subnet-group
    • Description: Subnet group for Redis cluster
    • VPC ID: Chọn caching-workshop-vpc của bạn

  1. Chọn availability zones và subnets:

    • Chọn cả hai private subnets từ các AZ khác nhau
    • Điều này đảm bảo tính khả dụng cao cho Redis cluster

  2. Nhấp Create

Bước 3: Tạo Redis OSS Cache

Điều Hướng Đến Redis OSS Caches

  1. Nhấp Redis OSS caches ở navigation bên trái

  1. Nhấp Create Redis OSS cache

Chọn Engine

  1. Chọn caching engine:
    • Engine: Redis OSS (giữ mặc định)
    • Lưu ý: Valkey được khuyến nghị để tiết kiệm chi phí, nhưng chúng ta sẽ sử dụng Redis OSS cho workshop này

Valkey cung cấp giá và hiệu suất nâng cao (tiết kiệm lên đến 33% với Serverless, 20% với node-based) và hoàn toàn tương thích với Redis OSS v7.0. Đối với production workloads, hãy cân nhắc Valkey như một drop-in replacement.

Chọn Deployment Option

  1. Chọn deployment option:
    • Deployment option: Design your own cache
    • Điều này cho phép chúng ta chọn các loại node và cấu hình cụ thể

Tùy chọn Serverless tự động scale nhưng “Design your own cache” cho chúng ta nhiều quyền kiểm soát hơn về loại node và chi phí cho workshop này.

Chọn Creation Method

  1. Chọn creation method:
    • Creation method: New cache
    • Restore from backup: Không chọn (chúng ta đang tạo cache trống mới)

Cấu Hình Cache Settings

  1. Cấu hình thông tin cache cơ bản:

    • Name: product-cache
    • Description: Redis cache for product catalog caching

Cấu Hình Default Settings

  1. Cấu hình cache specifications:
    • Use default settings: Bỏ chọn để tùy chỉnh
    • Engine version: 7.2 (stable mới nhất)
    • Port: 6379
    • Node type: cache.t3.micro
    • Multi-AZ: Enabled
    • Replicas: 1

Multi-AZ với replicas cung cấp tính khả dụng cao và khả năng automatic failover.

Bước 4: Cấu Hình Connectivity

Network Settings

  1. Cấu hình network settings:

    • Network type: IPv4
    • Subnet group: redis-subnet-group
    • Preferred availability zones: No preference

Security Settings

  1. Cấu hình security:

    • Security groups: Chọn redis-sg (xóa default)
    • Encryption at rest: Disabled (cho workshop)
    • Encryption in transit: Disabled (cho workshop)

Trong môi trường production, luôn bật encryption at rest và in transit để tuân thủ bảo mật.

Bước 5: Cấu Hình Advanced Settings

Backup Settings

  1. Cấu hình backup options:

    • Enable automatic backups: Yes
    • Backup retention period: 1 day
    • Backup window: No preference

Maintenance Settings

  1. Cấu hình maintenance:

    • Maintenance window: No preference
    • Topic for SNS notification: None (cho workshop)

Log Settings

  1. Cấu hình logging (tùy chọn):

    • Log format: Text
    • Log destination: None (cho workshop)

Bước 6: Review và Create

Review Configuration

  1. Review tất cả settings

  2. Xác minh:

    • Cache name và description
    • Engine version và node type
    • Network và security configuration
    • Backup và maintenance settings

  3. Nhấp Create Redis OSS cache

Việc tạo Redis cache mất 10-15 phút. Cache sẽ hiển thị trạng thái “Creating” trong thời gian này.

Bước 7: Giám Sát Cache Creation

Kiểm Tra Creation Progress

  1. Giám sát tiến trình tạo cache

  2. Bạn có thể thấy các node riêng lẻ đang được tạo

Xác Minh Cache Available

  1. Sau khi tạo xong, trạng thái cache sẽ hiển thị “Available”

  2. Nhấp vào tên cache để xem chi tiết

Bước 8: Ghi Lại Cache Endpoints

Primary Endpoint

  1. Ghi lại Primary endpoint cho write operations:
product-cache.xxxxxx.cache.amazonaws.com:6379

Reader Endpoint

  1. Ghi lại Reader endpoint cho read operations:
product-cache-ro.xxxxxx.cache.amazonaws.com:6379

Bước 9: Test Redis Connectivity

Launch Test Instance

  1. Sử dụng cùng test EC2 instance từ DAX testing, hoặc khởi chạy instance mới:

    • AMI: Amazon Linux 2023
    • Instance type: t3.micro
    • Subnet: Một trong các private subnets của bạn
    • Security group: app-sg

Install Redis CLI

  1. Kết nối đến test instance và cài đặt Redis CLI:
# Update system
sudo yum update -y

# Install Redis CLI
sudo yum install -y redis6

Test Redis Connection

  1. Kết nối đến Redis cache của bạn:
# Connect to primary endpoint
redis-cli -h product-cache.xxxxxx.cache.amazonaws.com -p 6379
  1. Test các Redis operations cơ bản:
# Test connection
PING

# Set a test key
SET test:key "Hello Redis from Workshop"

# Get the key
GET test:key

# Set with expiration
SETEX product:PROD001 300 '{"name":"Laptop Pro","price":999.99}'

# Check TTL
TTL product:PROD001

# Get product data
GET product:PROD001

# Check Redis info
INFO server

Bước 10: Cấu Hình Redis cho Application Use

Set Memory Policy

  1. Cấu hình memory eviction policy:
# Connect to primary endpoint
redis-cli -h product-cache.xxxxxx.cache.amazonaws.com -p 6379

# Set LRU eviction policy
CONFIG SET maxmemory-policy allkeys-lru

# Verify configuration
CONFIG GET maxmemory-policy

Test Cache Functionality

  1. Test cache behavior với TTL:
# Set multiple products with different TTLs
SETEX product:PROD001 300 '{"id":"PROD001","name":"Laptop Pro","price":999.99,"category":"Electronics"}'
SETEX product:PROD002 600 '{"id":"PROD002","name":"Smartphone X","price":699.99,"category":"Electronics"}'
SETEX product:PROD003 900 '{"id":"PROD003","name":"Cloud Guide","price":49.99,"category":"Books"}'

# Check all keys
KEYS product:*

# Check TTL for each key
TTL product:PROD001
TTL product:PROD002
TTL product:PROD003

# Get cached data
GET product:PROD001

Bước 11: Giám Sát Redis Performance

Enable CloudWatch Metrics

  1. Trong ElastiCache console, đi đến tab Monitoring

  2. Các metrics chính cần giám sát:

    • CPUUtilization: CPU usage qua các nodes
    • DatabaseMemoryUsagePercentage: Memory utilization
    • CacheHits/CacheMisses: Cache effectiveness
    • NetworkBytesIn/Out: Network traffic
    • Evictions: Số lượng keys bị evicted

Bước 12: Ghi Lại Redis Configuration

Ghi lại thông tin sau cho cấu hình ứng dụng:

Redis Cache Information

  • Cache Name: product-cache
  • Primary Endpoint: product-cache.xxxxxx.cache.amazonaws.com:6379
  • Reader Endpoint: product-cache-ro.xxxxxx.cache.amazonaws.com:6379
  • Node Type: cache.t3.micro
  • Replica Count: 1
  • Security Group: redis-sg
  • Subnet Group: redis-subnet-group

Performance Characteristics

  • Latency: Sub-millisecond cho cached data
  • Throughput: ~100,000 operations mỗi giây
  • Memory: ~555 MB available (t3.micro)
  • Eviction Policy: allkeys-lru

Khắc Phục Các Vấn Đề Thường Gặp

Vấn Đề: Không Thể Kết Nối Với Redis

Nguyên Nhân Có Thể:

  • Security group chặn traffic
  • Cấu hình endpoint không đúng
  • Vấn đề kết nối mạng

Giải Pháp:

  • Xác minh security group cho phép inbound traffic trên port 6379
  • Kiểm tra Redis endpoint URL và port
  • Đảm bảo client ở cùng VPC với Redis cache

Vấn Đề: Memory Usage Cao

Nguyên Nhân Có Thể:

  • Quá nhiều dữ liệu được cached
  • Không có TTL được set trên keys
  • Memory leak trong ứng dụng

Giải Pháp:

  • Giám sát memory usage trong CloudWatch
  • Set các giá trị TTL phù hợp
  • Sử dụng các cấu trúc dữ liệu tiết kiệm memory
  • Cân nhắc các loại node lớn hơn

Các Bước Tiếp Theo

Thiết lập ElastiCache Redis của bạn giờ đã hoàn thành! Bạn có:

✅ Redis OSS Cache với primary và replica nodes
✅ Multi-AZ deployment cho tính khả dụng cao
✅ Subnet Group được cấu hình cho private network access
✅ Security Group cho phép application access
✅ Automatic backups được bật
✅ CloudWatch monitoring được cấu hình
✅ Connection tested và xác minh

Lợi Ích Redis Đã Đạt Được:

  • Sub-millisecond latency cho cached application data
  • High throughput với 100K+ operations mỗi giây
  • Automatic failover với Multi-AZ deployment
  • Flexible data structures cho các tình huống caching phức tạp

Sử dụng primary endpoint cho read/write operations và reader endpoint cho read-only operations để phân phối tải và cải thiện hiệu suất.

Tiếp theo, chúng ta sẽ triển khai ứng dụng Node.js sẽ sử dụng cả Redis và DAX cho multi-layer caching.
