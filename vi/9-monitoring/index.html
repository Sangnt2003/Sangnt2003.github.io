Giám Sát và Cảnh Báo

Trong bước này, chúng ta sẽ tạo một CloudWatch dashboard toàn diện để giám sát kiến trúc multi-layer caching của chúng ta và thiết lập automated alerts cho proactive issue detection.

Bước 1: Tạo CloudWatch Dashboard

Điều Hướng Đến CloudWatch Console

  1. Mở AWS Management Console

  2. Điều hướng đến CloudWatch service

  3. Nhấp Dashboards ở navigation bên trái

  4. Nhấp Create dashboard

Cấu Hình Dashboard

  1. Cấu hình dashboard settings:

    • Dashboard name: MultiLayerCachingDashboard
    • Description: Monitoring dashboard for multi-layer caching workshop

  2. Nhấp Create dashboard

  1. Nhấp Add widget

  2. Chọn Line chart type

  3. Cấu hình ALB metrics:

    • Metrics: AWS/ApplicationELB

  4. Cấu hình widget settings:

    • Widget type: Line

Bước 6: Thêm Custom Application Metrics

Tạo Custom Metrics Script

  1. SSH vào EC2 instance của bạn và tạo custom metrics script:
nano send-custom-metrics.sh
  1. Thêm custom metrics script:
#!/bin/bash

# Get application statistics
STATS=$(curl -s http://localhost:3000/stats)

# Extract metrics using jq
TOTAL_REQUESTS=$(echo $STATS | jq -r '.total_requests // 0')
REDIS_HITS=$(echo $STATS | jq -r '.redis_hits // 0')
DAX_HITS=$(echo $STATS | jq -r '.dax_hits // 0')
DYNAMODB_HITS=$(echo $STATS | jq -r '.dynamodb_hits // 0')
ERRORS=$(echo $STATS | jq -r '.errors // 0')

# Calculate hit rates
if [ $TOTAL_REQUESTS -gt 0 ]; then
    CACHE_HIT_RATE=$(echo "scale=2; ($REDIS_HITS + $DAX_HITS) * 100 / $TOTAL_REQUESTS" | bc)
    REDIS_HIT_RATE=$(echo "scale=2; $REDIS_HITS * 100 / $TOTAL_REQUESTS" | bc)
else
    CACHE_HIT_RATE=0
    REDIS_HIT_RATE=0
fi

# Send metrics to CloudWatch
aws cloudwatch put-metric-data \
    --namespace "CachingApp/Performance" \
    --metric-data \
    MetricName=TotalRequests,Value=$TOTAL_REQUESTS,Unit=Count \
    MetricName=RedisHits,Value=$REDIS_HITS,Unit=Count \
    MetricName=DAXHits,Value=$DAX_HITS,Unit=Count \
    MetricName=DynamoDBHits,Value=$DYNAMODB_HITS,Unit=Count \
    MetricName=Errors,Value=$ERRORS,Unit=Count \
    MetricName=CacheHitRate,Value=$CACHE_HIT_RATE,Unit=Percent \
    MetricName=RedisHitRate,Value=$REDIS_HIT_RATE,Unit=Percent

echo "Custom metrics sent to CloudWatch"
  1. Làm script executable:
chmod +x send-custom-metrics.sh

Thiết Lập Cron Job

  1. Thiết lập cron job để gửi metrics mỗi phút:
# Edit crontab
crontab -e

# Add this line to run every minute
* * * * * /home/ec2-user/caching-app/send-custom-metrics.sh

Thêm Custom Metrics Widget

  1. Thêm custom metrics vào dashboard:

    • Widget type: Line
    • Metrics: CachingApp/Performance
    • Metric names: CacheHitRate, RedisHitRate
    • Title: Application Cache Performance

Bước 7: Tạo CloudWatch Alarms

Tạo High Response Time Alarm

  1. Điều hướng đến Alarms trong CloudWatch

  2. Nhấp Create alarm

  3. Cấu hình ALB response time alarm:

    • Metric: AWS/ApplicationELB > TargetResponseTime
    • LoadBalancer: caching-app-alb
    • Statistic: Average
    • Period: 5 minutes

  4. Set alarm conditions:

    • Threshold type: Static
    • Condition: Greater than 500 (milliseconds)
    • Datapoints to alarm: 2 out of 3

  5. Cấu hình alarm actions:

    • Alarm state trigger: In alarm
    • SNS topic: Tạo topic mới caching-alerts
    • Email: Địa chỉ email của bạn

  6. Đặt tên alarm:

    • Alarm name: High-Response-Time-ALB
    • Description: ALB response time is above 500ms

Tạo Low Cache Hit Rate Alarm

  1. Tạo alarm cho low cache hit rate:

    • Metric: CachingApp/Performance > CacheHitRate
    • Condition: Less than 80 (percent)
    • Name: Low-Cache-Hit-Rate

Tạo High Error Rate Alarm

  1. Tạo alarm cho high error rate:

    • Metric: AWS/ApplicationELB > HTTPCode_Target_5XX_Count
    • Condition: Greater than 10 (count)
    • Name: High-Error-Rate-ALB

Tạo Redis High CPU Alarm

  1. Tạo alarm cho Redis high CPU:

    • Metric: AWS/ElastiCache > CPUUtilization
    • CacheClusterId: product-cache-001
    • Condition: Greater than 80 (percent)
    • Name: Redis-High-CPU

Bước 8: Cấu Hình Log Insights

Thiết Lập Log Groups

  1. Điều hướng đến Log groups trong CloudWatch

  2. Tạo log group cho application logs:

    • Log group name: /aws/ec2/caching-app
    • Retention: 7 days

Cấu Hình CloudWatch Agent

  1. Cài đặt và cấu hình CloudWatch agent trên EC2:
# Create CloudWatch agent configuration
sudo nano /opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json
  1. Thêm agent configuration:
{
    "logs": {
        "logs_collected": {
            "files": {
                "collect_list": [
                    {
                        "file_path": "/var/log/caching-app/app.log",
                        "log_group_name": "/aws/ec2/caching-app",
                        "log_stream_name": "{instance_id}-app.log"
                    }
                ]
            }
        }
    },
    "metrics": {
        "namespace": "CWAgent",
        "metrics_collected": {
            "cpu": {
                "measurement": [
                    "cpu_usage_idle",
                    "cpu_usage_iowait",
                    "cpu_usage_user",
                    "cpu_usage_system"
                ],
                "metrics_collection_interval": 60
            },
            "disk": {
                "measurement": [
                    "used_percent"
                ],
                "metrics_collection_interval": 60,
                "resources": [
                    "*"
                ]
            },
            "mem": {
                "measurement": [
                    "mem_used_percent"
                ],
                "metrics_collection_interval": 60
            }
        }
    }
}
  1. Start CloudWatch agent:
# Start the agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
    -a fetch-config \
    -m ec2 \
    -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json \
    -s

Bước 9: Tạo Log Insights Queries

Tạo Performance Query

  1. Điều hướng đến Log Insights trong CloudWatch

  2. Tạo query cho performance analysis:

fields @timestamp, @message
| filter @message like /Cache HIT|Cache MISS/
| stats count() by bin(5m)
| sort @timestamp desc

Tạo Error Analysis Query

  1. Tạo query cho error analysis:
fields @timestamp, @message
| filter @message like /ERROR|error/
| stats count() by bin(1h)
| sort @timestamp desc

Khắc Phục Monitoring Issues

Vấn Đề: Metrics Không Xuất Hiện

Nguyên Nhân Có Thể:

  • IAM permissions không đủ
  • CloudWatch agent không chạy
  • Incorrect metric namespace

Giải Pháp:

  • Xác minh IAM role có CloudWatch permissions
  • Kiểm tra agent status: sudo systemctl status amazon-cloudwatch-agent
  • Xác minh metric names và namespaces

Vấn Đề: Alarms Không Trigger

Nguyên Nhân Có Thể:

  • Incorrect threshold values
  • Insufficient datapoints
  • SNS topic không được cấu hình

Giải Pháp:

  • Review alarm configuration và thresholds
  • Kiểm tra alarm history cho evaluation details
  • Xác minh SNS topic và email subscription

Vấn Đề: Custom Metrics Missing

Nguyên Nhân Có Thể:

  • Script execution errors
  • Cron job không chạy
  • Application endpoint unavailable

Giải Pháp:

  • Test script manually: ./send-custom-metrics.sh
  • Kiểm tra cron job: crontab -l
  • Xác minh application đang responding

Best Practices cho Production

Monitoring Strategy

  • Proactive alerting: Set thresholds trước khi issues xảy ra
  • Comprehensive coverage: Giám sát tất cả layers của stack
  • Regular review: Điều chỉnh thresholds dựa trên actual performance

Alert Management

  • Escalation procedures: Định nghĩa ai được thông báo khi nào
  • Alert fatigue prevention: Tránh quá nhiều false positives
  • Documentation: Duy trì runbooks cho common issues
