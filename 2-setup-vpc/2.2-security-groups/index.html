Create Security Groups

Security groups act as virtual firewalls that control inbound and outbound traffic for AWS resources. We’ll create specific security groups for each component of our caching architecture.

Security Group Architecture

We’ll create four security groups:

  • Application Security Group (app-sg) - For EC2 instances
  • Redis Security Group (redis-sg) - For ElastiCache
  • DAX Security Group (dax-sg) - For DynamoDB DAX
  • Load Balancer Security Group (alb-sg) - For Application Load Balancer

Step 1: Navigate to Security Groups

  1. In the VPC Console, click Security Groups in the left navigation

  2. Click Create security group

Step 2: Create Application Security Group

Basic Configuration

  1. Configure the application security group:

    • Security group name: app-sg
    • Description: Security group for application servers
    • VPC: Select your caching-workshop-vpc

Inbound Rules

  1. Add inbound rules for the application:

Rule 1: HTTP Access

  • Type: HTTP
  • Protocol: TCP
  • Port range: 80
  • Source: 0.0.0.0/0
  • Description: HTTP access from internet

Rule 2: Application Port

  • Type: Custom TCP
  • Protocol: TCP
  • Port range: 3000
  • Source: 0.0.0.0/0
  • Description: Application port access

Rule 3: SSH Access

  • Type: SSH
  • Protocol: TCP
  • Port range: 22
  • Source: My IP
  • Description: SSH access for management

Outbound Rules

  1. Keep the default outbound rule (All traffic to 0.0.0.0/0)

  1. Click Create security group

Step 3: Create Redis Security Group

Basic Configuration

  1. Create the Redis security group:

    • Security group name: redis-sg
    • Description: Security group for ElastiCache Redis
    • VPC: Select your caching-workshop-vpc

Inbound Rules

  1. Add inbound rule for Redis:

Rule 1: Redis Access

  • Type: Custom TCP
  • Protocol: TCP
  • Port range: 6379
  • Source: Custom (select app-sg)
  • Description: Redis access from application servers

We’re allowing access only from the application security group, following the principle of least privilege.

  1. Click Create security group

Step 4: Create DAX Security Group

Basic Configuration

  1. Create the DAX security group:

    • Security group name: dax-sg
    • Description: Security group for DynamoDB DAX
    • VPC: Select your caching-workshop-vpc

Inbound Rules

  1. Add inbound rule for DAX:

Rule 1: DAX Access

  • Type: Custom TCP
  • Protocol: TCP
  • Port range: 8111
  • Source: Custom (select app-sg)
  • Description: DAX access from application servers

  1. Click Create security group

Step 5: Create Load Balancer Security Group

Basic Configuration

  1. Create the load balancer security group:

    • Security group name: alb-sg
    • Description: Security group for Application Load Balancer
    • VPC: Select your caching-workshop-vpc

Inbound Rules

  1. Add inbound rules for the load balancer:

Rule 1: HTTP Access

  • Type: HTTP
  • Protocol: TCP
  • Port range: 80
  • Source: 0.0.0.0/0
  • Description: HTTP access from internet

Rule 2: HTTPS Access (Optional)

  • Type: HTTPS
  • Protocol: TCP
  • Port range: 443
  • Source: 0.0.0.0/0
  • Description: HTTPS access from internet

  1. Click Create security group

Security Best Practices Implemented

✅ Principle of Least Privilege: Each security group only allows necessary traffic
✅ Defense in Depth: Multiple layers of security controls
✅ Source-Based Access: Using security groups as sources instead of IP ranges
✅ Port Specificity: Only opening required ports
✅ Management Access: SSH access restricted to your IP

Troubleshooting Common Issues

Issue: Cannot Select Security Group as Source

Cause: Security groups must be in the same VPC

Solution: Verify all security groups are created in the correct VPC

Issue: Application Cannot Connect to Redis/DAX

Cause: Security group rules not properly configured

Solution:

  • Verify port numbers (Redis: 6379, DAX: 8111)
  • Confirm source security group is correct
  • Check outbound rules allow traffic

Issue: Internet Access Not Working

Cause: Security group blocking traffic or routing issues

Solution:

  • Verify inbound rules allow HTTP/HTTPS
  • Check route tables point to Internet Gateway
  • Confirm NAT Gateway configuration for private subnets

Next Steps

Your network security is now properly configured! You have:

✅ Application Security Group for EC2 instances
✅ Redis Security Group for ElastiCache access
✅ DAX Security Group for DynamoDB DAX access
✅ Load Balancer Security Group for internet traffic
✅ Least-privilege access between components
✅ Proper traffic flow from internet to backend services

Security groups are stateful, meaning if you allow inbound traffic on a port, the corresponding outbound traffic is automatically allowed.
