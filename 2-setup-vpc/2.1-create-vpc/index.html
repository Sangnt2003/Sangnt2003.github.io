Create VPC

In this step, we’ll create a Virtual Private Cloud (VPC) with all the necessary networking components for our multi-layer caching architecture.

Step 1: Navigate to VPC Console

  1. Open the AWS Management Console
  2. Navigate to the VPC service

  1. Click Create VPC

Step 2: Choose VPC Creation Method

  1. Select VPC and more to create VPC with associated resources

The “VPC and more” option automatically creates subnets, route tables, internet gateway, and NAT gateways, saving time and ensuring proper configuration.

Step 3: Configure VPC Settings

Basic VPC Configuration

  1. Configure the basic VPC settings:

    • Name tag auto-generation: caching-workshop
    • IPv4 CIDR block: 10.0.0.0/16
    • IPv6 CIDR block: No IPv6 CIDR block
    • Tenancy: Default

Subnet Configuration

  1. Configure subnets for high availability:

    • Number of Availability Zones: 2
    • Number of public subnets: 2
    • Number of private subnets: 2

NAT Gateway Configuration

  1. Configure NAT gateways for outbound internet access:

    • NAT gateways: 1 per AZ
    • VPC endpoints: None (for this workshop)

Using 1 NAT gateway per AZ provides high availability but increases costs. For cost optimization in non-production environments, you could use 1 NAT gateway total.

Step 4: Create VPC

  1. Click Create VPC

VPC creation will take 2-3 minutes. The process creates all associated resources including subnets, route tables, internet gateway, and NAT gateways.

Step 5: Verify VPC Creation

  1. Once created, you’ll see the success message:

  1. Click View VPC to see the created resources

Step 6: Explore Created Resources

VPC Dashboard

  1. Navigate to the VPC Dashboard to see all created resources:

Subnets Overview

  1. Check the Subnets section to verify proper distribution:

Verify you have:

  • 2 Public subnets in different AZs
  • 2 Private subnets in different AZs
  • Proper CIDR allocation (e.g., 10.0.1.0/24, 10.0.2.0/24, etc.)

Route Tables

  1. Check Route Tables to ensure proper routing:

Verify:

  • Public route table: Routes 0.0.0.0/0 to Internet Gateway
  • Private route tables: Route 0.0.0.0/0 to NAT Gateways

Subnet Information

  • Public Subnet 1: subnet-xxxxxxxxx (AZ: us-east-1a)
  • Public Subnet 2: subnet-xxxxxxxxx (AZ: us-east-1b)
  • Private Subnet 1: subnet-xxxxxxxxx (AZ: us-east-1a)
  • Private Subnet 2: subnet-xxxxxxxxx (AZ: us-east-1b)

Keep this information handy as you’ll need these IDs when creating security groups, launching instances, and configuring other AWS services.

Troubleshooting Common Issues

Issue: VPC Creation Fails

Possible Causes:

  • Insufficient permissions
  • CIDR block conflicts
  • Service limits reached

Solutions:

  • Verify IAM permissions include VPC creation rights
  • Choose a different CIDR block
  • Check AWS service limits in your account

Issue: NAT Gateway Creation Fails

Possible Causes:

  • Insufficient Elastic IP addresses
  • Public subnet not properly configured

Solutions:

  • Request additional Elastic IP addresses
  • Verify public subnets have routes to Internet Gateway
