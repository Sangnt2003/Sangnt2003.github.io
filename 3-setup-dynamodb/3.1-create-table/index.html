Create DynamoDB Table

In this step, we’ll create a DynamoDB table to store our product catalog data. This table will serve as the source of truth for our multi-layer caching architecture.

Step 1: Navigate to DynamoDB Console

  1. Open the AWS Management Console
  2. Navigate to the DynamoDB service

  1. Click Create table

Step 2: Configure Table Settings

Basic Table Configuration

  1. Enter the table configuration:

    • Table name: ProductCatalog
    • Partition key: ProductID (String)
    • Sort key: Category (String)

We’re using a composite primary key (partition key + sort key) to allow multiple products in different categories and enable efficient queries.

Table Settings

  1. Configure table settings:

    • Table settings: Default settings
    • Read/write capacity settings: On-demand

On-demand billing is perfect for workshops and unpredictable workloads. You only pay for the read and write requests you use.

Advanced Settings (Optional)

  1. Expand Additional settings if you want to configure:

    • Table class: Standard
    • Encryption: Owned by Amazon DynamoDB
    • Point-in-time recovery: Disabled (for workshop)
    • Deletion protection: Disabled (for workshop)

Step 3: Create Table

  1. Review your configuration:

  2. Click Create table

Table creation takes 1-2 minutes. The table will show “Creating” status initially.

Step 4: Verify Table Creation

  1. Once created, you’ll see the table in “Active” status:

  1. Click on the table name to view details:

  1. Note the Table ARN - you’ll need this for DAX configuration:
arn:aws:dynamodb:us-east-1:123456789012:table/ProductCatalog

Step 8: Document Table Information

Record the following information for use in subsequent steps:

Table Information

  • Table Name: ProductCatalog
  • Table ARN: arn:aws:dynamodb:us-east-1:123456789012:table/ProductCatalog
  • Partition Key: ProductID (String)
  • Sort Key: Category (String)
  • Billing Mode: On-demand

Sample Data Summary

  • Total Items: 5 products
  • Categories: Electronics (3), Books (2)
  • Price Range: $49.99 - $999.99

Performance Characteristics

Expected Performance

  • Read Latency: 1-10ms (without DAX)
  • Write Latency: 1-10ms
  • Throughput: Up to 40,000 RCU/WCU per partition
  • Consistency: Eventually consistent reads (default)

Optimization Tips

  • Hot Partitions: Monitor for uneven access patterns
  • Item Size: Keep items under 400KB for best performance
  • Query Patterns: Design keys to support your access patterns
  • Indexes: Use GSI/LSI for additional query patterns

Troubleshooting Common Issues

Issue: Table Creation Fails

Possible Causes:

  • Invalid table name or key names
  • Insufficient permissions
  • Service limits reached

Solutions:

  • Use alphanumeric characters and underscores only
  • Verify IAM permissions include DynamoDB actions
  • Check AWS service limits

Issue: Cannot Add Items

Possible Causes:

  • Missing required key attributes
  • Item size too large
  • Invalid JSON format

Solutions:

  • Ensure ProductID and Category are provided
  • Keep items under 400KB
  • Validate JSON syntax

Issue: Queries Return No Results

Possible Causes:

  • Incorrect key values
  • Case sensitivity issues
  • Wrong query syntax

Solutions:

  • Verify exact key values
  • Check for case-sensitive matches
  • Use PartiQL editor to test queries
