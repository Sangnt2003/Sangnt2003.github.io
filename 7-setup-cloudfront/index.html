7. Setup CloudFront CDN

In this step, we’ll create a CloudFront distribution to provide global edge caching for our multi-layer caching application.

Step 1: Navigate to CloudFront Console

  1. Open the AWS Management Console
  2. Navigate to the CloudFront service
  3. Click Create distribution

Step 2: Configure Origin Settings

Origin Domain

  1. Configure the origin settings:

    • Origin domain: Enter your ALB DNS name 
      caching-app-alb-xxxxxxxxx.us-east-1.elb.amazonaws.com
    • Protocol: HTTP only (for workshop)
    • HTTP port: 80

Origin Path

  1. Configure origin path (optional):

    • Origin path: Leave empty
    • Name: Auto-generated based on domain

Additional Origin Settings

  1. Configure additional settings:

    • Add custom header: None
    • Enable Origin Shield: No (for workshop)

Step 3: Configure Default Cache Behavior

Path Pattern

  1. Configure cache behavior:

    • Path pattern: Default (*)
    • Compress objects automatically: Yes

Viewer Protocol Policy

  1. Configure viewer protocol:

    • Viewer protocol policy: Redirect HTTP to HTTPS
    • Allowed HTTP methods: GET, HEAD, OPTIONS, PUT, POST, PATCH, DELETE

Cache Key and Origin Requests

  1. Configure cache key settings:

    • Cache policy: Create new policy or use existing
    • Origin request policy: None
    • Response headers policy: None

Create Custom Cache Policy

  1. Click Create policy to create a custom cache policy:

    • Name: CachingAppPolicy
    • Description: Cache policy for caching application
    • Default TTL: 300 seconds (5 minutes)
    • Maximum TTL: 3600 seconds (1 hour)
    • Minimum TTL: 0 seconds

Cache Key Settings

  1. Configure cache key settings:

    • Headers: None
    • Query strings: All
    • Cookies: None

  2. Click Create

Step 4: Configure Distribution Settings

Price Class

  1. Configure distribution settings:

    • Price class: Use all edge locations (best performance)
    • AWS WAF web ACL: None

Alternate Domain Names

  1. Configure domain settings:

    • Alternate domain names (CNAMEs): Leave empty for workshop
    • Custom SSL certificate: Default CloudFront certificate

Default Root Object

  1. Configure default root object:

    • Default root object: Leave empty
    • Standard logging: Off (for workshop)

Description and Comments

  1. Add description:

    • Description: CloudFront distribution for multi-layer caching workshop
    • Distribution state: Enabled

Step 5: Review and Create

Review Configuration

  1. Review all settings
  2. Click Create distribution

CloudFront distribution deployment takes 15-20 minutes. The distribution will show “Deploying” status during this time.

Step 6: Monitor Distribution Deployment

Check Deployment Status

  1. Monitor the distribution deployment
  2. The status will change from “Deploying” to “Enabled”

Note Distribution Domain

  1. Once deployed, note the Distribution domain name:
d1234567890123.cloudfront.net

Step 7: Test CloudFront Distribution

Test Basic Connectivity

  1. Test the CloudFront distribution:
# Test health endpoint through CloudFront
curl https://d1234567890123.cloudfront.net/health

Test Application Endpoints

  1. Test all application endpoints:
# Test product endpoint
curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

# Test products list
curl "https://d1234567890123.cloudfront.net/products"

# Test cache statistics
curl https://d1234567890123.cloudfront.net/stats

Step 8: Configure Cache Behaviors

Create API Cache Behavior

  1. Go to the Behaviors tab and click Create behavior

  2. Configure API-specific caching:

    • Path pattern: /product/*
    • Origin: Your ALB origin
    • Cache policy: Create new policy for API

API Cache Policy

  1. Create API cache policy:

    • Name: APIResponsePolicy
    • Default TTL: 300 seconds
    • Maximum TTL: 600 seconds
    • Query strings: All
    • Headers: Include Authorization if needed

Create Stats Behavior

  1. Create behavior for stats endpoint:

    • Path pattern: /stats
    • Cache policy: Create no-cache policy
    • TTL: 0 seconds (no caching)

Step 9: Test Cache Performance

Test Cache Miss

  1. Clear any existing cache and test:
# First request (cache miss)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Test Cache Hit

  1. Make the same request again:
# Second request (cache hit)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Check Response Headers

  1. Check CloudFront cache headers:
# Check cache headers
curl -I "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Look for headers like:

  • X-Cache: Hit from cloudfront (cache hit)
  • X-Cache: Miss from cloudfront (cache miss)
  • Age: 120 (time since cached)

Step 10: Configure Cache Invalidation

Create Invalidation

  1. Go to the Invalidations tab and click Create invalidation

  2. Configure invalidation paths:

    • Object paths: 
      /product/*
/products
/stats

  3. Click Create invalidation

Monitor Invalidation

  1. Monitor invalidation progress

Invalidations take 5-15 minutes to complete across all edge locations.

Step 11: Monitor CloudFront Performance

CloudWatch Metrics

  1. Go to the Monitoring tab to view metrics

Key metrics to monitor:

  • Requests: Number of requests to CloudFront
  • BytesDownloaded: Data transferred to viewers
  • CacheHitRate: Percentage of requests served from cache
  • OriginLatency: Response time from origin
  • 4xxErrorRate: Client error rate
  • 5xxErrorRate: Server error rate

Real-time Logs (Optional)

  1. Enable real-time logs for detailed monitoring

Step 12: Performance Comparison

Test Performance Improvement

  1. Compare response times:
# Direct ALB access
time curl "http://caching-app-alb-xxxxxxxxx.us-east-1.elb.amazonaws.com/product/PROD001?category=Electronics"

# CloudFront access (after cache warm-up)
time curl "https://d1234567890123.cloudfront.net/product/PROD001?category=Electronics"

Global Performance Test

  1. Test from different locations using online tools:
  • GTmetrix: Test from multiple global locations
  • Pingdom: Global performance monitoring
  • WebPageTest: Detailed performance analysis

Step 13: Document CloudFront Configuration

Record the following information:

CloudFront Distribution Information

  • Distribution ID: E1234567890123
  • Domain Name: d1234567890123.cloudfront.net
  • Origin: ALB DNS name
  • Status: Enabled
  • Price Class: All edge locations

Cache Behaviors

  • Default: 5-minute TTL, all query strings
  • API Endpoints: 5-minute TTL, optimized for API responses
  • Stats Endpoint: No caching for real-time data

Performance Characteristics

  • Global latency: 10-50ms (depending on edge location)
  • Cache hit ratio target: 80%+
  • Origin offload: 70%+ reduction in origin requests

Troubleshooting Common Issues

Issue: Distribution Not Accessible

Possible Causes:

  • Distribution still deploying
  • Origin not accessible
  • DNS propagation delay

Solutions:

  • Wait for deployment to complete (15-20 minutes)
  • Test origin directly first
  • Use distribution domain name, not custom domain

Issue: High Cache Miss Rate

Possible Causes:

  • Query strings not configured properly
  • Headers affecting cache key
  • TTL too short

Solutions:

  • Review cache policy configuration
  • Check query string and header settings
  • Increase TTL for stable content

Issue: Origin Errors

Possible Causes:

  • ALB or application issues
  • Security group blocking CloudFront
  • Origin timeout

Solutions:

  • Check ALB and application health
  • Verify security groups allow CloudFront IPs
  • Increase origin timeout settings

Security Best Practices

Origin Access Control

  • Restrict origin access: Only allow CloudFront to access ALB
  • Security groups: Update ALB security group to only allow CloudFront

SSL/TLS Configuration

  • Viewer protocol: Redirect HTTP to HTTPS
  • Origin protocol: Use HTTPS when possible
  • Security headers: Add security headers via response headers policy
