4. Setup ElastiCache Redis

In this step, we’ll create an ElastiCache Redis cluster that will serve as our application-level cache. This will be the first layer of caching that our application checks before falling back to DAX and DynamoDB.

Step 1: Navigate to ElastiCache Console

  1. Open the AWS Management Console
  2. Navigate to the ElastiCache service

  1. Click Get started or Create if this is your first time

Step 2: Create Subnet Group

Navigate to Subnet Groups

  1. Click Subnet groups in the left navigation

  2. Click Create subnet group

Configure Subnet Group

  1. Enter subnet group details:

    • Name: redis-subnet-group
    • Description: Subnet group for Redis cluster
    • VPC ID: Select your caching-workshop-vpc

  1. Select availability zones and subnets:

    • Choose both private subnets from different AZs
    • This ensures high availability for the Redis cluster

  2. Click Create

Step 3: Create Redis OSS Cache

Navigate to Redis OSS Caches

  1. Click Redis OSS caches in the left navigation

  1. Click Create Redis OSS cache

Choose Engine

  1. Select the caching engine:
    • Engine: Redis OSS (keep default)
    • Note: Valkey is recommended for cost savings, but we’ll use Redis OSS for this workshop

Valkey offers enhanced price and performance (up to 33% savings with Serverless, 20% with node-based) and is fully compatible with Redis OSS v7.0. For production workloads, consider Valkey as a drop-in replacement.

Choose Deployment Option

  1. Select deployment option:
    • Deployment option: Design your own cache
    • This allows us to select specific node types and configurations

Serverless option automatically scales but “Design your own cache” gives us more control over node types and costs for this workshop.

Choose Creation Method

  1. Select creation method:
    • Creation method: New cache
    • Restore from backup: Not selected (we’re creating a new empty cache)

Configure Cache Settings

  1. Configure basic cache information:

    • Name: product-cache
    • Description: Redis cache for product catalog caching

Configure Default Settings

  1. Configure cache specifications:
    • Use default settings: Uncheck to customize
    • Engine version: 7.2 (latest stable)
    • Port: 6379
    • Node type: cache.t3.micro
    • Multi-AZ: Enabled
    • Replicas: 1

Multi-AZ with replicas provides high availability and automatic failover capabilities.

Step 4: Configure Connectivity

Network Settings

  1. Configure network settings:

    • Network type: IPv4
    • Subnet group: redis-subnet-group
    • Preferred availability zones: No preference

Security Settings

  1. Configure security:

    • Security groups: Select redis-sg (remove default)
    • Encryption at rest: Disabled (for workshop)
    • Encryption in transit: Disabled (for workshop)

In production environments, always enable encryption at rest and in transit for security compliance.

Step 5: Configure Advanced Settings

Backup Settings

  1. Configure backup options:

    • Enable automatic backups: Yes
    • Backup retention period: 1 day
    • Backup window: No preference

Maintenance Settings

  1. Configure maintenance:

    • Maintenance window: No preference
    • Topic for SNS notification: None (for workshop)

Log Settings

  1. Configure logging (optional):

    • Log format: Text
    • Log destination: None (for workshop)

Step 6: Review and Create

Review Configuration

  1. Review all settings

  2. Verify:

    • Cache name and description
    • Engine version and node type
    • Network and security configuration
    • Backup and maintenance settings

  3. Click Create Redis OSS cache

Redis cache creation takes 10-15 minutes. The cache will show “Creating” status during this time.

Step 7: Monitor Cache Creation

Check Creation Progress

  1. Monitor the cache creation progress

  2. You can see individual nodes being created

Verify Cache is Available

  1. Once created, the cache status will show “Available”

  2. Click on the cache name to view details

Step 8: Note Cache Endpoints

Primary Endpoint

  1. Note the Primary endpoint for write operations: 
product-cache.xxxxxx.cache.amazonaws.com:6379

Reader Endpoint

  1. Note the Reader endpoint for read operations: 
product-cache-ro.xxxxxx.cache.amazonaws.com:6379

Step 9: Test Redis Connectivity

Launch Test Instance

  1. Use the same test EC2 instance from the DAX testing, or launch a new one:

    • AMI: Amazon Linux 2023
    • Instance type: t3.micro
    • Subnet: One of your private subnets
    • Security group: app-sg

Install Redis CLI

  1. Connect to your test instance and install Redis CLI:
# Update system
sudo yum update -y

# Install Redis CLI
sudo yum install -y redis6

Test Redis Connection

  1. Connect to your Redis cache:
# Connect to primary endpoint
redis-cli -h product-cache.xxxxxx.cache.amazonaws.com -p 6379
  1. Test basic Redis operations:
# Test connection
PING

# Set a test key
SET test:key "Hello Redis from Workshop"

# Get the key
GET test:key

# Set with expiration
SETEX product:PROD001 300 '{"name":"Laptop Pro","price":999.99}'

# Check TTL
TTL product:PROD001

# Get product data
GET product:PROD001

# Check Redis info
INFO server

Step 10: Configure Redis for Application Use

Set Memory Policy

  1. Configure memory eviction policy:
# Connect to primary endpoint
redis-cli -h product-cache.xxxxxx.cache.amazonaws.com -p 6379

# Set LRU eviction policy
CONFIG SET maxmemory-policy allkeys-lru

# Verify configuration
CONFIG GET maxmemory-policy

Test Cache Functionality

  1. Test cache behavior with TTL:
# Set multiple products with different TTLs
SETEX product:PROD001 300 '{"id":"PROD001","name":"Laptop Pro","price":999.99,"category":"Electronics"}'
SETEX product:PROD002 600 '{"id":"PROD002","name":"Smartphone X","price":699.99,"category":"Electronics"}'
SETEX product:PROD003 900 '{"id":"PROD003","name":"Cloud Guide","price":49.99,"category":"Books"}'

# Check all keys
KEYS product:*

# Check TTL for each key
TTL product:PROD001
TTL product:PROD002
TTL product:PROD003

# Get cached data
GET product:PROD001

Step 11: Monitor Redis Performance

Enable CloudWatch Metrics

  1. In the ElastiCache console, go to the Monitoring tab

  2. Key metrics to monitor:

    • CPUUtilization: CPU usage across nodes
    • DatabaseMemoryUsagePercentage: Memory utilization
    • CacheHits/CacheMisses: Cache effectiveness
    • NetworkBytesIn/Out: Network traffic
    • Evictions: Number of evicted keys

Step 12: Document Redis Configuration

Record the following information for application configuration:

Redis Cache Information

  • Cache Name: product-cache
  • Primary Endpoint: product-cache.xxxxxx.cache.amazonaws.com:6379
  • Reader Endpoint: product-cache-ro.xxxxxx.cache.amazonaws.com:6379
  • Node Type: cache.t3.micro
  • Replica Count: 1
  • Security Group: redis-sg
  • Subnet Group: redis-subnet-group

Performance Characteristics

  • Latency: Sub-millisecond for cached data
  • Throughput: ~100,000 operations per second
  • Memory: ~555 MB available (t3.micro)
  • Eviction Policy: allkeys-lru

Troubleshooting Common Issues

Issue: Cannot Connect to Redis

Possible Causes:

  • Security group blocking traffic
  • Incorrect endpoint configuration
  • Network connectivity issues

Solutions:

  • Verify security group allows inbound traffic on port 6379
  • Check Redis endpoint URL and port
  • Ensure client is in same VPC as Redis cache

Issue: High Memory Usage

Possible Causes:

  • Too much data cached
  • No TTL set on keys
  • Memory leak in application

Solutions:

  • Monitor memory usage in CloudWatch
  • Set appropriate TTL values
  • Use memory-efficient data structures
  • Consider larger node types
