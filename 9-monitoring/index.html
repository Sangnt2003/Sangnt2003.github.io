Monitoring and Alerting

In this step, we’ll create a comprehensive CloudWatch dashboard to monitor our multi-layer caching architecture and set up automated alerts for proactive issue detection.

Step 1: Create CloudWatch Dashboard

Navigate to CloudWatch Console

  1. Open the AWS Management Console

  2. Navigate to the CloudWatch service

  3. Click Dashboards in the left navigation

  4. Click Create dashboard

Configure Dashboard

  1. Configure dashboard settings:

    • Dashboard name: MultiLayerCachingDashboard
    • Description: Monitoring dashboard for multi-layer caching workshop

  2. Click Create dashboard

Step 2: Add Application Load Balancer Metrics

Add ALB Widget

  1. Click Add widget

  2. Select Line chart type

  3. Configure ALB metrics:

    • Metrics: AWS/ApplicationELB
    • Metric name: RequestCount, TargetResponseTime
    • LoadBalancer: Select your caching-app-alb

  4. Configure widget settings:

    • Widget title: Application Load Balancer Performance
    • Y-axis: Left axis for RequestCount, Right axis for ResponseTime
    • Period: 5 minutes

  5. Click Create widget

Add ALB Error Rate Widget

  1. Add another widget for error rates:

    • Widget type: Line
    • Metrics: HTTPCode_Target_4XX_Count, HTTPCode_Target_5XX_Count
    • Title: Application Error Rates

Step 6: Add Custom Application Metrics

Create Custom Metrics Script

  1. SSH into your EC2 instance and create a custom metrics script:
nano send-custom-metrics.sh
  1. Add the custom metrics script:
#!/bin/bash

# Get application statistics
STATS=$(curl -s http://localhost:3000/stats)

# Extract metrics using jq
TOTAL_REQUESTS=$(echo $STATS | jq -r '.total_requests // 0')
REDIS_HITS=$(echo $STATS | jq -r '.redis_hits // 0')
DAX_HITS=$(echo $STATS | jq -r '.dax_hits // 0')
DYNAMODB_HITS=$(echo $STATS | jq -r '.dynamodb_hits // 0')
ERRORS=$(echo $STATS | jq -r '.errors // 0')

# Calculate hit rates
if [ $TOTAL_REQUESTS -gt 0 ]; then
    CACHE_HIT_RATE=$(echo "scale=2; ($REDIS_HITS + $DAX_HITS) * 100 / $TOTAL_REQUESTS" | bc)
    REDIS_HIT_RATE=$(echo "scale=2; $REDIS_HITS * 100 / $TOTAL_REQUESTS" | bc)
else
    CACHE_HIT_RATE=0
    REDIS_HIT_RATE=0
fi

# Send metrics to CloudWatch
aws cloudwatch put-metric-data \
    --namespace "CachingApp/Performance" \
    --metric-data \
    MetricName=TotalRequests,Value=$TOTAL_REQUESTS,Unit=Count \
    MetricName=RedisHits,Value=$REDIS_HITS,Unit=Count \
    MetricName=DAXHits,Value=$DAX_HITS,Unit=Count \
    MetricName=DynamoDBHits,Value=$DYNAMODB_HITS,Unit=Count \
    MetricName=Errors,Value=$ERRORS,Unit=Count \
    MetricName=CacheHitRate,Value=$CACHE_HIT_RATE,Unit=Percent \
    MetricName=RedisHitRate,Value=$REDIS_HIT_RATE,Unit=Percent

echo "Custom metrics sent to CloudWatch"
  1. Make the script executable:
chmod +x send-custom-metrics.sh

Set Up Cron Job

  1. Set up a cron job to send metrics every minute:
# Edit crontab
crontab -e

# Add this line to run every minute
* * * * * /home/ec2-user/caching-app/send-custom-metrics.sh

Add Custom Metrics Widget

  1. Add custom metrics to dashboard:

    • Widget type: Line

    • Metric names: CacheHitRate, RedisHitRate
    • Title: Application Cache Performance

Step 7: Create CloudWatch Alarms

Create High Response Time Alarm

  1. Navigate to Alarms in CloudWatch

  2. Click Create alarm

  3. Configure ALB response time alarm:

    • Metric: AWS/ApplicationELB > TargetResponseTime
    • LoadBalancer: caching-app-alb
    • Statistic: Average
    • Period: 5 minutes

  4. Set alarm conditions:

    • Threshold type: Static
    • Condition: Greater than 500 (milliseconds)
    • Datapoints to alarm: 2 out of 3

  5. Configure alarm actions:

    • Alarm state trigger: In alarm
    • SNS topic: Create new topic caching-alerts
    • Email: Your email address

  6. Name the alarm:

    • Alarm name: High-Response-Time-ALB
    • Description: ALB response time is above 500ms

Create Low Cache Hit Rate Alarm

  1. Create alarm for low cache hit rate:

    • Metric: CachingApp/Performance > CacheHitRate
    • Condition: Less than 80 (percent)
    • Name: Low-Cache-Hit-Rate

Create High Error Rate Alarm

  1. Create alarm for high error rate:

    • Metric: AWS/ApplicationELB > HTTPCode_Target_5XX_Count
    • Condition: Greater than 10 (count)
    • Name: High-Error-Rate-ALB

Create Redis High CPU Alarm

  1. Create alarm for Redis high CPU:

    • Metric: AWS/ElastiCache > CPUUtilization
    • CacheClusterId: product-cache-001
    • Condition: Greater than 80 (percent)
    • Name: Redis-High-CPU

Step 8: Configure Log Insights

Set Up Log Groups

  1. Navigate to Log groups in CloudWatch

  2. Create log group for application logs:

    • Log group name: /aws/ec2/caching-app
    • Retention: 7 days

Configure CloudWatch Agent

  1. Install and configure CloudWatch agent on EC2:
# Create CloudWatch agent configuration
sudo nano /opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json
  1. Add agent configuration:
{
    "logs": {
        "logs_collected": {
            "files": {
                "collect_list": [
                    {
                        "file_path": "/var/log/caching-app/app.log",
                        "log_group_name": "/aws/ec2/caching-app",
                        "log_stream_name": "{instance_id}-app.log"
                    }
                ]
            }
        }
    },
    "metrics": {
        "namespace": "CWAgent",
        "metrics_collected": {
            "cpu": {
                "measurement": [
                    "cpu_usage_idle",
                    "cpu_usage_iowait",
                    "cpu_usage_user",
                    "cpu_usage_system"
                ],
                "metrics_collection_interval": 60
            },
            "disk": {
                "measurement": [
                    "used_percent"
                ],
                "metrics_collection_interval": 60,
                "resources": [
                    "*"
                ]
            },
            "mem": {
                "measurement": [
                    "mem_used_percent"
                ],
                "metrics_collection_interval": 60
            }
        }
    }
}
  1. Start CloudWatch agent:
# Start the agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
    -a fetch-config \
    -m ec2 \
    -c file:/opt/aws/amazon-cloudwatch-agent/etc/amazon-cloudwatch-agent.json \
    -s

Step 9: Create Log Insights Queries

Create Performance Query

  1. Navigate to Log Insights in CloudWatch

  2. Create query for performance analysis:

fields @timestamp, @message
| filter @message like /Cache HIT|Cache MISS/
| stats count() by bin(5m)
| sort @timestamp desc

Create Error Analysis Query

  1. Create query for error analysis:
fields @timestamp, @message
| filter @message like /ERROR|error/
| stats count() by bin(1h)
| sort @timestamp desc

Troubleshooting Monitoring Issues

Issue: Metrics Not Appearing

Possible Causes:

  • IAM permissions insufficient
  • CloudWatch agent not running
  • Incorrect metric namespace

Solutions:

  • Verify IAM role has CloudWatch permissions
  • Check agent status: sudo systemctl status amazon-cloudwatch-agent
  • Verify metric names and namespaces

Issue: Alarms Not Triggering

Possible Causes:

  • Incorrect threshold values
  • Insufficient datapoints
  • SNS topic not configured

Solutions:

  • Review alarm configuration and thresholds
  • Check alarm history for evaluation details
  • Verify SNS topic and email subscription

Issue: Custom Metrics Missing

Possible Causes:

  • Script execution errors
  • Cron job not running
  • Application endpoint unavailable

Solutions:

  • Test script manually: ./send-custom-metrics.sh
  • Check cron job: crontab -l
  • Verify application is responding

Best Practices for Production

Monitoring Strategy

  • Proactive alerting: Set thresholds before issues occur
  • Comprehensive coverage: Monitor all layers of the stack
  • Regular review: Adjust thresholds based on actual performance

Alert Management

  • Escalation procedures: Define who gets notified when
  • Alert fatigue prevention: Avoid too many false positives
  • Documentation: Maintain runbooks for common issues
